# Storage and Contained-Environment Hygiene Policy

Load before builds, tests, containers, VMs, simulators/emulators, browser automation or profiles, local AI, generated media, package/model caches, temporary databases, generated worktrees, remote previews, or equivalent contained environments. Leave each execution environment better than found, but only within proven owned scope.

Keep source and Git metadata in the repository of record. Approved repository and generated-output roots come from the active local profile. Never use a synchronized review or document lane for active repositories, worktrees, package state, builds, media, or scratch output. Route disposable, cached, heavyweight, and agent-created non-model output to the project's approved generated-output lane, using project-scoped `Worktrees`, `Artifacts`, `Tmp`, `DerivedData`, `target`, `Node`, `Playwright`, and `Models` directories where applicable. Active model weights, downloaded model caches, and model-runner stores remain on fast internal storage by default; generated media, datasets, evaluations, conversions, and temporary inference output do not share that exception.

Before heavy work, verify the lane and use this lifecycle: assign a unique run/environment identity; verify exact ownership; classify retention as `disposable`, `persistent`, `shared`, `evidence`, or `unknown`; record bounded baseline usage; perform exact teardown; and report closeout usage and residuals. Predeclare retention at creation in an assignment- or runtime-bound creation record that identifies the exact object and immutable engine/object identity; for processes, include PID plus start identity. At teardown, that creation record plus the immutable engine/object identity is required deletion authority. Run/Compose identifiers, labels, tags, and digests only corroborate identity and cannot independently authorize deletion. A familiar name or location, worker claim, path/name, age/TTL, disk pressure, or port alone never proves ownership or disposable status. Inventory and reports contain identifiers, classes, sizes, dispositions, and before/after usage only; never print secrets.

Remove only exact, proven-disposable, run-owned artifacts after their consumers stop and retention/evidence checks pass. Immediately before teardown, recheck exact ownership and active references to avoid check/delete races; make teardown idempotent and verify either absence or intentionally retained state afterward. Preserve by default persistent database volumes; shared images, caches, networks, model stores, and browser profiles; and all unknown, evidence, or project-retained state; and anything referenced by an accepted candidate, reproducibility, rollback, validation, or evidence. If the approved lane is unavailable, stop unless the user authorizes a local fallback; report its path, contents, reason, and residual cleanup obligation. Redirect output only when supported without harming correctness.

For Docker, teardown may address only exact lane-owned stopped containers, networks, disposable images/build output, and explicitly disposable volumes. Never run `docker system prune`, image/volume/builder-cache prune, a wildcard or glob cleanup, parent-root or recursive broad deletion, or a Docker.raw manipulation or relocation trick. Docker.raw bloat is an observed example of the general contract, not a separate tool policy. Remote branches, registries, cloud previews, and hosted resources require separate external deletion authority. An explicit user cleanup request may name another project, but each named repository/root is resolved and admitted independently; never infer sibling, ancestor, or parent-root authority.

Record disk evidence before and after heavy runs, plus storage-growth and residual obligations. Do not claim a clean run when closeout is incomplete; the project result still continues. A cleanup success record never hides a failed teardown: retain the explicit residual. Cleanup or helper failure preserves state and the residual obligation, never grants broad deletion or blocks the project.

Hard-rule rent: this prevents disk/storage exhaustion, cross-run collisions, and stale service/resource leakage, which are expensive to recover and can destroy or contaminate another run's state. Enforcement cost is bounded identity, usage, teardown, and closeout evidence. Escalation path: Seat `0` resolves authority or retention ambiguity. Safe fallback: preserve the exact state and report it.
